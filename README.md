# 상상Book-E

> 같이 밥 먹고, 같이 만나고, 같이 이용하는 한성 캠퍼스 연결 플랫폼
> 한성 아이디어 경진대회 출품작 (팀 상상Book-E)

## 서비스 소개

상상Book-E 는 한성대 학생을 위한 **모바일 우선 웹 앱**입니다. 세 가지가 한 앱 안에서 이어집니다.

| 영역 | 하는 일 |
|---|---|
| **캠퍼스 스페이스** | 시간표를 모아 팀원이 **함께 비는 시간**을 찾고, 그 시간에 쓸 수 있는 **교내 시설을 예약**합니다. |
| **라운지** *(이번 배포에서는 숨김)* | 같은 시간에 접속한 학우들이 아바타로 돌아다니는 2D 광장입니다. 테이블에 앉아 **미팅·밥약**을 잡고, 자리가 차면 그 사람들만의 **단톡방**이 열립니다. |
| **학교 계정 연동** | 학교 포털 계정을 한 번 연동하면 **학교 시간표 가져오기 · 내 학교 예약 보기 · 시설 바로 신청**을 앱 안에서 할 수 있습니다. |

하단 탭은 **홈 · 시간표 · 회의** 이고(라운지를 켜면 **라운지** 탭이 하나 더 생깁니다), 내 정보는 헤더 오른쪽 사람 아이콘으로 갑니다. 글자 크기(90~150%)와 선명한 화면(고대비)은 모든 화면 헤더에서 바꿀 수 있습니다.

### 캠퍼스 스페이스 기능

- **회원가입 / 로그인** — 가입은 **① 학교 계정(학번·포털 비밀번호)으로 학생 인증 → ② 서비스 아이디·비밀번호 입력·확인 → ③ 학교 계정 연동 동의 → ④ 가입 완료** 순서이고, 가입이 끝나면 학교 연동도 끝나 있습니다. 로그인은 서비스 아이디·비밀번호로 합니다. (학교 메일 인증코드 가입 코드는 지우지 않고 꺼 두었습니다 — 서버 `EMAIL_SIGNUP_ENABLED=1` 과 클라이언트 `features.ts` 의 `EMAIL_SIGNUP_ENABLED`)
- **내 시간표** — 월~금 09:00~22:00, 30분 단위. 격자에서 탭하거나 길게 눌러 끌어 일정을 추가하고, 매주/그 날만 반복을 고르며, 학교 강의시간표에서 과목을 검색해 담을 수 있습니다.
- **회의(팀)** — 숫자 4자리 코드로 만들고 참가합니다. 참여자를 고르고 팀원 시간표를 겹쳐 봅니다. 코드를 붙여넣을 때 공백·하이픈이 섞여 있어도 받아 줍니다.
- **회의 예약** — 팀원 전체의 공통 여유 시간 계산 → 날짜 → 이용 가능한 시설 → **학교에 바로 신청** 순서입니다. 시설 예약은 학교 계정을 연동해야만 할 수 있고(앱 안에만 남는 예약은 없습니다), 학교에 보내기 전에 내용을 한 번 더 확인하며, 신청을 보내지 않고 닫으면 예약은 만들어지지 않습니다.
- **홈** — 다가오는 예약, 내 회의, 이번 주 시간표를 모아 보여 줍니다. (라운지를 켜면 내 라운지 약속도 함께 나옵니다.)

### 라운지 기능

> **현재 꺼져 있습니다.** 서버 API(`/api/lounge`)와 화면 코드는 들어 있지만, 화면 검토를 마치지 못해 이번 배포에서는 숨겼습니다. 켜려면 `client/src/features.ts` 의 `LOUNGE_ENABLED` 를 `true` 로 바꾸고 다시 빌드하세요. 켜기 전에 화면별 점검(특히 지도·빠른 매칭·단톡방)이 필요합니다.

- **프로필** — 닉네임·단과대·학과·입학년도·아바타(동물과 색)를 한 번 만들면 라운지에 들어갈 수 있습니다. 실명·이메일·학과는 다른 사람에게 보이는 응답에 넣지 않습니다.
- **월드 지도** — 광장, 미팅 라운지, 밥약 식당 세 구역입니다. 지도를 눌러 아바타를 걷게 하고, 구역 간판을 누르면 그 구역의 게시판이 열립니다. 접속자는 3초마다 갱신되고 45초 동안 신호가 없으면 사라집니다. 이모트(👋 😄 🙏 ❤️)는 5초 동안 머리 위에 보입니다.
- **목록 모드** — 지도 대신 목록으로도 같은 기능을 모두 쓸 수 있습니다. 화면 낭독기와 키보드 사용자를 위한 대안이기도 합니다.
- **미팅** — "N:N 할 사람?" 글을 올리면 우리 쪽·상대 쪽 빈 의자에 **선착순으로 앉습니다.** "같은 학과 제외" 옵션이 있습니다.
- **밥약** — 모집글에 신청하면 주최자가 **승인**합니다.
- **빠른 매칭** — 날짜·장소 종류·인원·시간대를 고르면 대기열에 들어가고, 맞는 사람이 모이면 후보 방이 열립니다. 시간 투표 → 전원 수락 → 확정 순서이고, 한 명이라도 거절하거나 시간이 지나면 방이 깨지고 나머지는 다시 대기합니다.
- **단톡방** — 정원이 차면 그 사람들만의 방이 열립니다(3초 간격 갱신). 차단한 사람의 메시지는 가려집니다.
- **매너온도 · 노쇼** — 모임이 끝난 뒤 서로 평가합니다. 나머지 전원이 "안 왔어요"라고 해야 노쇼로 확정되고(온도 −5, 경고 +1), 경고가 2번이면 이용이 정지됩니다. 한 사람의 오해로 경고가 찍히지 않게 한 규칙입니다.
- **차단 · 신고** — 한쪽이 차단하면 양쪽의 목록·접속자·매칭·사용자 조회에서 서로 사라집니다. 서로 다른 3명이 신고하면 자동으로 이용이 제한됩니다.
- **관리자 화면** — 신고 처리(처리 완료·반려·정지·정지 해제)와 이용 통계를 봅니다.
- **시간표 연결** — 모임 시각이 내 시간표 수업과 겹치면 "수업과 겹쳐요" 배지가 붙습니다(막지는 않습니다).

### 이 프로젝트에 없는 것

- **셔틀버스 기능은 없습니다.** 노선·시간표·실시간 위치 모두 범위에서 뺐고, 라운지 지도 구역도 광장·미팅 라운지·밥약 식당 셋뿐입니다.
- 소켓 기반 실시간 통신은 없습니다. 서버리스 배포에서 어렵기 때문에 접속자와 단톡방은 폴링(3초)입니다.
- 전체 채팅, 친구, 푸시 알림, 아바타 꾸미기는 없습니다.
- 소개팅과 팀빌딩 모임(`team`) 화면은 라운지에 없습니다. 팀 모임은 "회의" 탭이 맡습니다.

## 기술 스택

| 구분 | 사용한 것 |
|---|---|
| 클라이언트 | React 19, TypeScript(strict), Vite 6, react-router-dom 6 (UI 라이브러리 없이 KRDS 토큰 기반 자체 컴포넌트) |
| 서버 | Node.js, Express 4, TypeScript(`tsx` 로 실행), JWT 쿠키 인증(`jsonwebtoken`, `bcryptjs`), `nodemailer` |
| 데이터 | PostgreSQL(`pg`). 로컬에서는 DB 를 따로 설치하지 않도록 PGlite(임베디드 Postgres)를 씁니다. 배포는 Supabase 같은 Postgres |
| 공용 계약 | `shared/` — 서버와 클라이언트가 같이 쓰는 타입·상수·규칙 |
| 테스트·도구 | Vitest, Playwright(화면 확인 스크립트) |
| 배포 | Vercel(정적 파일 + 서버리스 함수). Netlify, Fly.io(Docker) 설정도 들어 있습니다 |

## 실행

Node.js 24 에서 개발했습니다(`Dockerfile` 과 같은 버전).

```bash
npm install
npm run dev          # API 서버와 클라이언트를 함께 실행
```

- 클라이언트 http://localhost:5273 (Vite, `/api` 는 서버로 프록시)
- API 서버 http://localhost:3101 (`API_PORT` 로 바꿀 수 있습니다)
- 데이터: 로컬 PGlite. 프로젝트가 OneDrive·Dropbox 같은 동기화 폴더 안에 있으면 `~/.sangsang-booke`, 아니면 `./data` 에 만들어지고(`DATA_DIR` 로 바꿀 수 있음) 최초 실행 시 테이블과 시설이 자동으로 생깁니다. `DATABASE_URL` 이 있으면 그 Postgres 를 씁니다.
- 서버만 / 클라이언트만 따로 실행하려면 `npm run dev:server`, `npm run dev:client` 를 씁니다.

그 밖의 스크립트(`package.json`):

| 명령 | 하는 일 |
|---|---|
| `npm run typecheck` | 서버와 클라이언트 타입 검사 |
| `npm run build` | 클라이언트를 `client/dist` 로 빌드 |
| `npm start` | 서버를 실행(`client/dist` 가 있으면 함께 서빙) |
| `npm test` | 단위·통합 테스트 |
| `npm run seed:demo` | 시연 데이터(시간표·회의·예약)를 개발 서버에 넣음 |
| `npm run shot -- <경로> <이름>` | 화면 캡처(아래 "화면 확인 도구") |

휴대폰으로 보려면 PC 와 같은 Wi-Fi 에서 `npx vite --config client/vite.config.ts --host` 로 열고 `http://<PC IP>:5273` 에 접속합니다.

### 환경 변수

`.env.example` 을 `.env` 로 복사해 값을 채웁니다(`.env` 는 git 에 올라가지 않습니다). 아래 다섯 가지가 핵심입니다.

| 이름 | 용도 | 비고 |
|---|---|---|
| `DATABASE_URL` | Postgres 연결 문자열 | **배포에서는 필수**(서버리스는 없으면 시작하지 않습니다). 로컬에서는 비우면 PGlite. Supabase 는 Transaction pooler(포트 6543) 문자열을 쓰고, 비밀번호의 특수문자는 URL 인코딩합니다 |
| `JWT_SECRET` | 로그인 쿠키(JWT) 서명 키 | **배포에서는 필수**. 로컬에서는 비우면 데이터 폴더의 `jwt-secret` 파일에 무작위 값을 만들어 씁니다. 학교 연동의 실패 가드가 학번을 해시할 때도 이 값을 씁니다 |
| `ADMIN_PASSWORD` | 관리자 계정 `admin1~3@hansung.ac.kr` 의 비밀번호 | 비워 두면 관리자 계정을 만들지 않습니다. 이미 있는 계정의 비밀번호는 바꾸지 않습니다 |
| `LOUNGE_DEV_SEED` | `1` 이면 개발용 시드 API(`POST /api/lounge/dev/seed`)를 엽니다 | `NODE_ENV=production` 이거나 서버리스(Vercel·Netlify·Lambda)면 `1` 이어도 열리지 않습니다 |
| `SCHOOL_MOCK_ORIGIN` | 학교 사이트 대신 부를 **가짜 학교 서버**의 주소(예: `http://127.0.0.1:4555`) | 개발·시험 전용. `localhost`·`127.0.0.1`·`[::1]` 주소만 받고, 운영·서버리스에서는 값이 있어도 무시합니다. 비우면 실제 학교 두 호스트로만 요청합니다 |

선택 값: `SMTP_HOST` `SMTP_PORT`(기본 587) `SMTP_USER` `SMTP_PASS` `MAIL_FROM` 은 가입 인증 메일 발송용입니다. 없으면 로컬에서는 인증코드가 **API 서버 콘솔**에 출력되고, 배포에서는 가입 메일을 보낼 수 없습니다. `API_PORT`(기본 3101), `DATA_DIR`(로컬 데이터 폴더)도 있습니다. 학교 메일 가입을 다시 켤 때(`EMAIL_SIGNUP_ENABLED=1`)만 쓰입니다.

### 개발용 데모 계정

모두 **개발 DB 에서만** 쓰는 계정입니다. 운영에는 만들지 않습니다.

- **라운지 데모 사용자** 아이디 `demo1` … `demo8` / 비밀번호 `Demo1234!` — 프로필과 샘플 모임(미팅 3개와 밥약 2개. 미팅 하나는 정원이 차서 단톡방이 열려 있고, 다른 하나는 한 자리만 남아 있습니다)이 함께 만들어집니다. `demo1` 과 `demo2` 는 같은 학과라 "같은 학과 제외" 동작을 눈으로 볼 수 있습니다.

  ```bash
  # 서버를 LOUNGE_DEV_SEED=1 로 시작한 뒤 (bash)
  LOUNGE_DEV_SEED=1 npm run dev
  # 다른 터미널에서 한 번 호출. 여러 번 불러도 같은 결과(멱등)입니다.
  curl -X POST http://localhost:3101/api/lounge/dev/seed
  ```

  PowerShell 에서는 `$env:LOUNGE_DEV_SEED='1'; npm run dev` 로 시작합니다.
- **관리자·시연 계정** `admin1~3@hansung.ac.kr` — 서버를 `ADMIN_PASSWORD` 와 함께 시작하면 만들어집니다. 시간표와 회의 "캡스톤 디자인 팀"까지 채우려면 아래 순서로 합니다. (예시 비밀번호 `Test1234!`)

  ```bash
  ADMIN_PASSWORD='Test1234!' npm run dev:server
  npm run seed:demo        # 다른 터미널
  ```

## 학교 계정 연동과 보안 모델

학교 포털의 학번·비밀번호를 연동하면 앱이 학교 사이트와 대신 상호작용합니다(시간표 가져오기, 내 학교 예약 보기, 시설 바로 신청, 라운지 프로필의 학과·입학년도 기본값). 비밀번호를 어떻게 다루는지는 아래 표 그대로이며, 한계도 숨기지 않습니다.

| 무엇 | 어디에 | 누가 풀 수 있나 |
|---|---|---|
| 복호화 **키**(AES-GCM 256) — 서비스 **아이디·비밀번호에서 브라우저가 만듭니다**(PBKDF2-SHA256 60만 번 → HKDF) | 이 브라우저의 `localStorage` (`sangsang-booke:school-key:<사용자id>`) | 비밀번호를 아는 사용자(=로그인한 기기) |
| **암호문** | 우리 DB(`users.school_cipher`) | 키 없이는 아무도 못 풉니다(우리 서버·DB 가 유출돼도) |
| **평문** 학번·비밀번호 | 어디에도 저장하지 않습니다 | 학교와 상호작용하는 **그 요청 하나** 동안만 서버 메모리에 있습니다 |

- 가입할 때 학교 계정으로 학생 인증(서버가 학교에 **한 번** 로그인)을 마치면, 브라우저가 서비스 아이디·비밀번호에서 만든 키로 학교 계정을 봉인한 *암호문*만 서버가 저장합니다. 서버는 키를 한 번도 받지 않습니다. 키를 만드는 방법(PBKDF2+HKDF, 아이디로 만든 소금)은 서버가 비밀번호를 저장하는 방법(bcrypt)과 다르고, 서버에 저장된 해시로는 키를 만들 수 없습니다.
- 학교 기능을 쓸 때는 브라우저가 암호문을 받아 로컬 키로 풀고, 그 평문을 해당 요청에만 실어 보냅니다. 서버는 로그·에러 메시지·DB·캐시·응답에 평문을 넣지 않습니다. 모든 `/api/school/*` 응답은 `Cache-Control: no-store` 입니다.
- **여러 기기에서 이어집니다**: 다른 기기에서 같은 아이디·비밀번호로 로그인하면 그 기기가 같은 키를 만들어 `localStorage` 에 두므로 연동이 이어집니다. 비밀번호를 잊으면 암호를 풀 수 없어 학교 계정을 다시 연동해야 합니다. 한계: 서버는 학교 기능을 쓰는 순간 평문을 잠깐 받고(요청 처리용), 로그인할 때 비밀번호를 받습니다 — 서버 운영자를 믿는 구조입니다. 연동을 해제하면 서버의 암호문이 지워집니다.
- **로그인 실패 가드** — 학교는 로그인을 10번 틀리면 계정을 잠급니다. 그 앞에서 앱이 먼저 멈춥니다. 연속 4회 실패까지는 잠금이 없고, **5번째 실패부터 30분 동안** 학교로 요청을 보내지 않습니다. 잠금이 끝나도 실패 횟수는 0 으로 돌리지 않습니다(돌리면 5+5=10 이 되어 학교 계정이 잠깁니다). 8회에 이르면 시간이 지나도 풀리지 않는 정지 상태가 되어, 학교 포털에서 새 비밀번호를 확인한 뒤 다시 연동해야 합니다. 실패 횟수는 학번 원문이 아니라 해시(HMAC)로만 저장합니다. 점검·네트워크 오류는 실패로 세지 않고, 실패 뒤에는 자동으로 다시 시도하지 않습니다.
- 서버가 학교로 보내는 호스트와 경로는 고정이고(사용자 입력은 URL 로 쓰지 않습니다), 요청 제한 시간은 10초, 응답은 2MB 까지만 받습니다. 시설 신청은 반드시 **미리보기 → 확인 → 제출** 순서이고, 결과가 불분명하면 자동으로 다시 보내지 않습니다.
- **한계**: 학교 사이트는 비밀번호 로그인만 받기 때문에, 학교 기능을 쓰는 순간에는 우리 서버가 평문을 잠깐 봅니다. 이 설계는 "저장된 데이터의 유출"을 막을 뿐, 서버 자체가 침해된 경우나 내 브라우저의 XSS 는 막지 못합니다.
- **실제 학교 사이트와는 자동 시험을 하지 않습니다**(틀린 계정으로 시험하면 학교 계정이 잠길 수 있기 때문). 파서·변환·가드·암호화는 고정된 가짜 응답으로 시험했고, 실제 학교에서의 동작은 화면에서 직접 확인해야 합니다. 처음 연동할 때 학교 응답이 예상과 달라 실패할 수 있습니다.

## 배포 (Vercel)

`vercel.json` 이 빌드와 라우팅을 정합니다: 빌드 `npm run build`, 출력 `client/dist`, `/api/*` 는 서버리스 함수(`api/index.ts`, Express 앱 그대로)로, 나머지는 `index.html` 로 보냅니다.

1. 저장소를 Vercel 프로젝트로 가져옵니다.
2. 환경 변수를 등록합니다: `DATABASE_URL`, `JWT_SECRET`(필수). 가입 메일을 쓰려면 `SMTP_*` 와 `MAIL_FROM`. 관리자 계정을 만들려면 `ADMIN_PASSWORD`.
3. `LOUNGE_DEV_SEED`·`SCHOOL_MOCK_ORIGIN` 은 등록하지 않습니다(등록해도 운영에서는 동작하지 않습니다).
4. 배포합니다. 첫 요청에서 테이블이 자동으로 만들어집니다.

서버리스라서 요청 제한(rate limit)은 인스턴스 메모리 기준이어서 약합니다. Fly.io(`fly.toml`, `Dockerfile`) 설정도 있으며 같은 환경 변수를 씁니다. (Netlify 설정은 2026-10-24 에 Vercel 로 모두 옮기며 지웠습니다)

## 테스트

```bash
npm test
```

Vitest 가 `server/**/*.test.ts`, `shared/**/*.test.ts`, `client/src/**/*.test.ts` 를 실행합니다. 모임·평판·안전·빠른 매칭·단톡방 규칙, 동시에 같은 의자에 앉는 경쟁, 학교 응답 파서와 로그인 가드, 학교 계정 금고(암호화) 등을 다룹니다. DB 가 필요한 시험은 임시 폴더의 PGlite 를 쓰므로 개발 DB 에 영향을 주지 않습니다. 화면(브라우저) 자동 시험은 없고, 화면은 아래 도구로 눈으로 확인합니다.

## 화면 확인 도구

개발 서버가 떠 있는 상태에서 Playwright 로 모바일 화면을 캡처합니다(결과는 `shots/`).

```bash
npm run shot -- timetable my-shot --user=admin1 --full      # 모바일 390×844 캡처
npm run shot -- account acc-150 --zoom=1.5                   # 글자 150%
npm run shot -- account acc-hc --contrast=high               # 선명한 화면
npm run shot -- lounge lounge-360 --user=demo1 --width=360 --height=740
```
