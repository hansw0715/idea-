# 라운지 — 설계 개요

> **⚠ 셔틀버스 기능은 사용자 지시로 범위에서 완전히 삭제되었다.** 이 문서나 다른 지시서에 셔틀·정류장·`/api/bus`·`BusSheet`·`bus` 구역이 남아 있어도 **무시한다**(만들지도, 없다고 지적하지도 않는다). 지도 구역은 광장·미팅 라운지·밥약 식당 셋이다.

> 같이 밥 먹고, 같이 만나고, 같이 이용하는 한성 캠퍼스 연결 플랫폼 — 그 "같이"가 일어나는 곳.

## 1. 한 줄 정의

**라운지 = 같은 시간에 접속한 학우들이 아바타로 돌아다니고, 의자에 앉아 밥약·미팅에 참여하는 2D 광장.**
실제 약속의 진실은 서버의 *모임(Gathering)* 이고, 지도는 그 모임을 **테이블과 의자**로 보여 주는 화면이다.
(원본 아이디어 코드: 사용자가 보내 준 `idea--master` — Next.js + 인메모리. 도메인 규칙은 그대로 옮기고 저장소는 Postgres 로 새로 만든다.)

하단 메뉴는 **홈 · 시간표 · 회의 · 라운지**. 내 정보는 헤더 오른쪽 사람 아이콘으로 간다.

## 2. 이번(1차)에 만드는 것 / 안 만드는 것

만드는 것
- 프로필(닉네임·단과대·학과·학번·아바타) — 라운지에 들어오려면 한 번 만든다
- 월드 지도: 광장 · 미팅 라운지 · 밥약 식당, 접속자 아바타(걷기·이모트), 테이블·의자
- 미팅: "N:N 할 사람?" 글 → 우리 쪽/상대 쪽 빈 의자에 **선착순 앉기**, 같은 과 제외 옵션
- 밥약: 모집글(주최자 **승인제**) + **빠른 매칭**(조건 → 대기 → 후보 방 → 시간 투표 → 전원 수락 → 확정)
- **단톡방**: 자리가 다 차면 그 사람들만의 방이 열림 (3초 폴링, 차단한 사람 메시지 가림)
- **매너온도 · 노쇼**: 모임 후 서로 평가, 나머지 전원이 "안 왔어요"면 노쇼 확정(온도 −5, 경고 +1, 경고 2회 정지)
- **차단 · 신고**: 차단은 양쪽에서 서로 사라짐, 서로 다른 3명이 신고하면 자동 제한, 관리자 처리
- **관리자 화면**: 신고 처리 · 이용 통계
- **연결**: 모임 시각이 내 시간표(수업)와 겹치면 "수업과 겹쳐요" 배지, 홈에 "내 라운지 약속"

안 만드는 것 (다음 단계)
- 팀빌딩 모임(kind 'team') 화면 — 도메인은 지원하지만 화면은 기존 "회의" 탭이 맡는다
- 셔틀버스 (사용자 결정으로 범위에서 제외)
- 전체 채팅, 친구, 알림 푸시, 소켓 실시간(서버리스라 폴링)
- 아바타 꾸미기(얼굴·색 선택만)

## 3. 월드 설계

### 3.1 지도 컨테이너
- 프레임 폭(최대 480px) 100%, `aspect-ratio: 360 / 760`. 좌표계는 **0~1 정규화**(x 가로, y 세로). 모든 요소는 `left/top` 을 `%` 로 배치하는 **실제 `<button>`** 이다.
- 바닥·장식은 인라인 SVG(`viewBox="0 0 360 760"`), 크기에 민감한 요소(아바타·의자·테이블)는 컨테이너 쿼리 단위(`cqw`, 컨테이너 폭의 1%)로 정해 **글자 확대(150%)에도 지도가 같은 비율**로 보이게 한다. 지도 위 글자는 `rem`(최소 1.3rem)이고 짧게 쓴다.
- 지도 컨테이너는 `role="group" aria-label="라운지 지도"`. 의미 있는 모든 요소는 `aria-label`(예: "미팅 테이블, 금요일 저녁 2:2, 2명 중 3명 앉음") 을 가진다.
- 페이지 세로 스크롤 안에서 지도가 자연스럽게 스크롤된다 (지도에 `touch-action` 을 막지 않는다).

### 3.2 구역(권장 좌표, viewBox 360×760 기준 — 구현에서 조정 가능)
```
y   0 ┌─ 광장 plaza ─────────────────────────────┐
      │  분수(180,76)  나무·벤치·산책로 장식     │
 150  └──────────────────────────────────────────┘
 158  ┌─ 미팅 라운지 meetup (카펫) ──────────────┐   라벨 "미팅 라운지" (16,170)
      │ 테이블 슬롯 6개 (2열×3행, 각 152×80)     │   중심: (96,230)(264,230)(96,318)(264,318)(96,406)(264,406)
 448  └──────────────────────────────────────────┘
 466  ┌─ 밥약 식당 meal ─────────────────────────┐   라벨 "밥약 식당" (16,478)
      │ 테이블 슬롯 4개 (2×2)  + 빠른 매칭 키오스크│   중심: (96,540)(264,540)(96,626)(264,626), 키오스크 (180,712)
 748  └──────────────────────────────────────────┘
```
- 구역 라벨/간판을 누르면 그 구역 **게시판 시트**(전체 모집글 목록 + "자리 만들기")가 열린다.
- 테이블 슬롯은 고정이다. 표시할 모임이 슬롯보다 많으면 **내 모임 → 마감 임박(가까운 약속) 순**으로 채우고 나머지는 게시판 시트에서 본다. 슬롯이 비어 있으면 "빈 테이블 — 자리 만들기"(눌러서 만들기).

### 3.3 테이블과 의자
- **미팅 테이블**: 직사각형. 윗줄 = "우리 쪽" 의자, 아랫줄 = "상대 쪽" 의자 (1:1 ~ 4:4 → 줄당 1~4개). 앉은 자리는 아바타, 빈 의자는 점선 의자.
- **밥약 테이블**: 원형. 정원 2~4 의자가 둘레에 놓인다. 승인제라 빈 의자를 눌러도 곧바로 앉지 않고 **신청 시트**가 열린다.
- 테이블 아래에 제목 한 줄(말줄임)과 시간(예: `금 19:00`). 정원이 다 차면 말풍선 아이콘(단톡방 열림)을 붙인다. 종료·취소된 모임은 지도에 그리지 않고 목록·게시판에만 둔다.
- 테이블을 누르면 `TableSheet`. **빈 의자를 누르면 같은 시트가 열리되 그 자리가 선택된 상태**이다 (실수로 약속이 확정되지 않게 항상 확인 버튼을 거친다).
- 내가 앉은 의자에는 "나" 표시. 한 사람은 **한 번만** 그려진다: 보이는 테이블에 앉아 있으면 의자에, 아니면 걷는 아바타로.

### 3.4 아바타 · 이동 · 접속자
- 내 아바타: 지도 바닥을 누르면 그 위치로 **걸어간다**(CSS transition `left/top`, 선형 0.9초; `prefers-reduced-motion` 이면 즉시 이동). 이동이 끝나면 `POST /presence`(위치·구역). 이동하지 않아도 20초마다 하트비트.
- 다른 접속자: `GET /presence` 를 3초마다(탭이 보일 때만) 받아 같은 transition 으로 **미끄러지듯** 옮긴다. 45초 동안 신호가 없으면 사라진다.
- 구역 판정은 클라이언트가 위치로 계산해 `zone` 을 같이 보낸다 (plaza / meetup / meal).
- 닉네임 라벨을 아바타 아래에 항상 보여 준다(흰 바탕 칩 + 1px 보더, 1.3rem). 아바타를 누르면 `UserSheet`(프로필 카드, 신고·차단).
- **이모트**: 지도 아래 고정 바(👋 😄 🙏 ❤️)를 누르면 내 머리 위에 말풍선이 5초 동안 뜨고 다른 접속자에게도 보인다.
- 상단에 "지금 N명 접속 중"(`aria-live="polite"`) 칩.

### 3.5 목록 모드 (접근성 대안 — 필수)
지도 위 전용 조작을 못 하거나 하고 싶지 않은 사람, 스크린 리더·키보드 사용자를 위해 상단에 **지도 | 목록** 전환을 둔다. 목록 모드는 같은 기능을 전부 담는다:
접속자 수 · 내 약속 · 미팅 글 · 밥약 글(각각 `GatheringListItem`) · 빠른 매칭 버튼 · 자리 만들기 버튼. 선택은 localStorage 에 기억(실패해도 동작). 지도 모드의 모든 동작은 목록 모드로도 가능해야 한다.

## 4. 시각 디자인 — "KRDS 사이트 분위기"에 맞춘 메타버스

원칙은 기존 앱과 같다 (`docs/UI-KIT.md`, `DESIGN.md`). 라운지는 *일러스트가 아니라 도구처럼 보이는 평면 도형 월드*다.
- 바닥은 **평면 색 면 + 1px 보더 + 4px 라운드**: 광장 `--gray-5`, 미팅 라운지 `--primary-5`, 밥약 식당 `--success-5`. 그림자·그라데이션·텍스처 없음(모달/시트/토스트 제외).
- 테이블은 흰 면 + 2px `--gray-60` 보더, 의자는 4px 라운드 사각(빈 의자는 점선 `--gray-40`). 장식(분수·나무·벤치)은 보더만 있는 단순 도형.
- 아바타: `parts/Avatar.tsx` (범주 색 `--m-1~8` 테두리 + 연한 바탕 + 동물 이모지). **색만으로 사람을 구분하지 않는다** — 닉네임 라벨이 항상 함께.
- 인디고(`--primary-50`)는 *행위* 자리에만: 선택된 의자·내 아바타 링·주요 버튼.
- 모션: KRDS 는 400ms 이하·스프링 금지. **아바타 걷기는 기능적 이동이라 0.9초 선형을 예외로 허용**하고, `prefers-reduced-motion` 에서는 즉시 이동한다. 그 밖의 전환(시트·토스트 등)은 기존 토큰(400ms)을 쓴다.
- 문장은 KRDS 보이스(정중한 -합니다/-해요, 명사형 제목, 빈 상태는 다음 행동 안내). 마케팅 문구·감탄 금지.

## 5. 서비스 연결

- **시간표**: 모임 `meetAt` 이 내 시간표와 겹치면 서버가 `viewer.timetableConflict`(겹치는 수업 이름)를 채우고, 목록·테이블 시트에 "수업과 겹쳐요: 자료구조" 배지를 보인다(막지는 않는다). 빠른 매칭 시간 구간 칩에도 같은 힌트(선택).
- **홈**: "내 라운지 약속"(`GET /mine`, 가까운 3건) 구역 → 눌러서 라운지로.
- **내 정보**: 라운지 프로필(아바타·닉네임·매너온도·경고), 차단한 사용자, (관리자면) 관리자 화면 링크.

## 6. 정직하게 말해 두는 한계 (화면·문서에 숨기지 않는다)

- 접속자·단톡방은 **폴링**(3초)이다. 진짜 실시간(소켓)은 서버리스 배포에서 어려워 다음 단계로 둔다.
- 노쇼 확정은 "나머지 전원이 안 왔어요"일 때만이다. 한 명의 오해로 경고가 찍히지 않게 한 의도된 규칙이다.
