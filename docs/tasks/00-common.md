## 작업 방식
1. 원본을 읽고 **기능 목록**을 먼저 뽑는다 (아래 지시서의 체크리스트 + 원본에서 발견한 것). 하나도 빠뜨리지 않는다. 조건부 메시지·엣지 케이스·15초 폴링·자동 포커스 같은 동작 디테일도 포함이다.
2. 모바일에 맞게 화면 구조를 다시 짜되, **동작은 같게** 유지한다. 데스크톱 전용 상호작용(hover 툴팁, window.confirm/prompt)은 모바일 대응(탭, `useConfirm`, 시트, 토스트)으로 바꾼다.
3. 구현 → `node_modules/.bin/tsc -p client/tsconfig.json` → `node scripts/shot.mjs …` 로 직접 화면을 **눈으로 확인**(이미지를 Read 로 열어 본다) → 고친다. 최소 360×740 과 390×844 두 폭에서, 그리고 `--zoom=1.5` 에서도 한 번씩 본다.
4. 보이는 것만이 아니라 **상호작용도 실제로 눌러 본다**: `scripts/lib.mjs` 로 Playwright 시나리오를 짜서 열기/닫기·제출·오류 경로를 확인한다. (키보드 Tab 이동과 포커스 링 포함)
5. 완료 전 점검: 타입 검사 통과, 콘솔 오류 없음(로그인 전 `/auth/me` 401 제외), 가로 넘침 없음, 직접 쓴 헥스 색 없음 (`grep -n "#[0-9a-fA-F]\{3,8\}" <내 파일>` 결과가 비어야 함), `font-weight: 500|600` 없음, 1.3rem 미만 글자 없음.

## 파일 소유권 (충돌 방지)
- 각자 지시서에 적힌 파일만 만들고 고친다. 남의 파일, 공통 파일(`styles/*`, `ui/*`, `shell/*`, `App.tsx`, `api.ts`, `types.ts`, `time.ts`, `useWeek.ts`, `auth.tsx`, `gridEntries.ts`, `reservationStatus.ts`)은 **수정하지 않는다.** 필요한 변경은 보고서 `foundationRequests` 에 "무엇을, 왜" 로 적는다.
- 다른 작업자의 파일에서 생기는 타입 오류는 작업 중의 일시적인 것일 수 있다. 1~2분 뒤 다시 확인하고, 남의 파일은 고치지 않는다.
- 개발 서버(5273/3101)를 끄거나 다시 시작하지 않는다. `git` 명령·커밋은 쓰지 않는다. 시연 DB 를 지우지 않는다.
- 새로 만드는 css 는 파일마다 고유 접두사(`auth-`, `home-`, `tt-`, `meet-` …)를 쓴다.
